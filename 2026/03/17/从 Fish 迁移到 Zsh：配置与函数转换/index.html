已知问题：分隔符空白

Starship 的 format 字符串中分隔符写死，但中间的模块可能为空（如 git 不在仓库时、语言版本不匹配时），导致  双分隔符。无优雅解法，要么忍受要么用 $all 自动格式（但会失去定制的渐变效果）。

环境变量同步

Fish 的 set -gx 对应 Zsh 的 export：

Fish Zsh
set -gx VAR value export VAR=value
set -gx PATH $PATH /new/path export PATH="$PATH:/new/path"
set -p PATH ~/.local/bin export PATH="$HOME/.local/bin:$PATH"

缩写/别名翻译

Fish 的 abbr（输入后展开）Zsh 没有原生等价物，用 alias 近似替代：

Fish abbr Zsh alias
abbr grub 'LANGUAGE=... sudo grub-mkconfig ...' alias grub='LANGUAGE=... sudo ...'
abbr fa fastfetch alias fa='fastfetch'
abbr reboot 'systemctl reboot' alias reboot='systemctl reboot'
abbr lsfg 'LSFG_PROCESS="miyu"' alias lsfg='export LSFG_PROCESS=miyu'

区别：fish 的 abbr 输入后按空格才展开，可以预览后再确认；zsh 的 alias 直接替换执行，没有预览步骤。

终端状态管理

问题

fish 在每次命令执行后自动恢复终端设置。zsh 不会，子进程留下的”脏”终端状态会直接继承。

典型场景：sl（蒸汽火车动画）通过管道传给 lolcat（彩虹色）后，sl 检测到 stdout 不是 TTY，行为异常，退出时没有恢复 raw 模式等终端设置。zsh 继承了这种脏状态，导致后续命令（如 shorin）的输出列对齐错乱。

解决

对有副作用的命令，函数内手动恢复终端：

恢复命令 作用
tput sgr0 重置文字颜色、粗体等显示属性
stty sane 恢复终端行设置（raw/cooked、回显等）

两者都不清屏。

通用建议

迁移任何涉及终端控制的命令（动画、TUI、管道穿过色工具）时，在 zsh 包装函数末尾加上 tput sgr0; stty sane 2>/dev/null。这能避免终端状态污染导致后续命令输出错乱（如 column 列对齐失败）。

注意：fish 这类问题不会出现，因为它每次命令后自动恢复终端。zsh 需要手动处理。
